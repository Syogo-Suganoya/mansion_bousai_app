# マンション防災カルテ

過密都市「東京」のマンション住民向け防災・避難支援アプリ（ハッカソンMVP）。
東京都のオープンデータと突合し、在宅避難の可否判定と避難所のリアルタイムニーズ集約を行う。

## 政策的位置づけ

- **都知事選公約**: 小池百合子知事3期目公約の「首都防衛」（セーフシティ施策）の一環であるマンション防災・避難所改革の強化（出典: [小池ゆりこ公式サイト 政策](https://www.yuriko.or.jp/policy)、都の「[マンション防災TOKYO 2024](https://www.bousai.metro.tokyo.lg.jp/taisaku/topics/1000019/1029124/1030150.html)」施策）
- **チームみらい政策マニフェスト**: その他重要分野「災害」政策（[policy.team-mir.ai/policies/other-important-fields](https://policy.team-mir.ai/policies/other-important-fields)）

※ このアプリは他案（13・14・15・16）と異なり、企画当初から特定の政策項目を直接引用したものではなく、後から政策テーマとの関連づけを行ったもの。

## 機能

- **ランディングページ（`/`）**
  - アプリでできること（4機能）の紹介と、実際の画面スクリーンショット付きの操作手順（STEP 1〜6）
- **防災カルテ（`/karte`）**
  - 発災時モード: 「在宅避難中（安全）/ 要救助 / 避難所へ移動開始」のワンタップ切替
  - 地域危険度判定: 住所入力 → 国土地理院APIでジオコーディング＋逆ジオコーディング → 町丁目単位で地域危険度・浸水想定とDB突合
  - 在宅避難適性診断: 築年・構造・階数からルールベースで定性評価
  - 在宅避難継続可能日数シミュレーター: 備蓄量から継続日数を算出、目標7日に対するゲージ表示
- **避難所デジタル目安箱（`/board`）**
  - 避難所の不足物資 / マンション住民の余剰備蓄をタグベースで投稿
  - 区×物資カテゴリ単位で需給を集計し、マッチング状況を表示（10秒ポーリングで自動更新）

## データについて

危険度判定は **東京都オープンデータAPI**（https://spec.api.metro.tokyo.lg.jp/spec/search）
からリアルタイムに取得する（APIキー不要、6時間インメモリキャッシュ）。

| データ | 提供元 | 取得方法 |
| :--- | :--- | :--- |
| 地域危険度測定調査（第9回・5,192町丁目） | 都市整備局 | 区名＋町丁目名で絞り込み |
| 浸水予想区域図（浸水深・地盤高、区部10流域） | 建設局 | 自宅周辺150m四方の座標範囲検索の最大値 |
| 消火栓・防火水槽等（13.5万件） | 東京消防庁 | 自宅周辺300m四方の座標範囲検索の件数 |
| 東京都防災マップ 避難所一覧（CC BY 4.0） | 総務局 | 区で絞り込み後、直線距離の近い順 |

`db/init/01_schema.sql` のサンプル危険度データは **API障害時のフォールバック** として残している
（サンプル利用時は画面にバッジ表示）。CityGML・点群データ（3D都市モデル）はAPI未提供のため、
ファイル配布からの事前変換が必要で今回は非採用（下記「今後の拡張」参照）。

※ 浸水予想区域図は都管理の中小河川・内水の想定であり、荒川等の大河川氾濫（国管理）は含まない。

## 今後の拡張（条件付き実現提案）

今回のMVPはコア機能（危険度判定＋備蓄シミュレーター＋目安箱）に絞ったデモ。
以下は技術的には実装可能だが、データ・運用面の前提条件が揃っていないため見送った機能。

| 難所 | 実現の前提条件 | 条件が揃った場合に実現できること |
| :--- | :--- | :--- |
| 避難所ニーズのリアルタイム集約 | 避難所運営者（自治体職員・学校教員）が発災時に投稿する運用体制の整備（自治体連携） | 空のダッシュボードではなく、実際の物資過不足が地域単位で可視化され、行政サプライチェーンと接続できる |
| 余剰備蓄マッチングの実効性 | 配送主体・衛生責任の所在を定めた制度設計（マンション管理組合・自治体間の協定） | 「誰が運ぶのか」が解決され、マッチング結果が実際の物資移動につながる |
| 危険度判定の正確性・鮮度 | 地域危険度調査（約5年周期）・浸水予想区域図の改定データが機械可読形式で継続提供されること | 常に最新の公的データに基づく判定が可能。あわせて「判定」ではなく「参考情報」と位置づける免責設計を行う |
| 建物情報の自動補完 | PLATEAU / 都市3DデジタルマップのLOD2属性（構造・階数・築年）の整備地域拡大 | ユーザーの手入力を廃し、住所入力だけで防災カルテが自動生成される |
| 発災時の可用性 | オフライン前提の設計（PWA化・静的フォールバック）と、輻輳・停電を想定したインフラ構成 | 通信障害下でも直近の危険度情報・避難ルートを参照可能 |
| 危険回避型の避難ルートナビ | 道路ネットワークデータ（OSM等）と浸水・火災危険度ポリゴンの重ね合わせ基盤（pgRouting等） | 危険エリアを回避コストとして組み込んだ本物の経路探索が提供できる |

課題の本質は技術ではなく運用・制度・データ提供体制にあるため、行政連携が実現の鍵になる。
